\noindent \textbf{Executive Summary \& Phase 2 Scope:}\\
Phase 2 extends ImageLab into an advanced, resource-constrained image processing architecture. Replacing naive full-frame matrix snapshots, Phase 2 implements a memory-budgeted history system that achieves an order-of-magnitude reduction in heap footprint through compact inverse transaction records, automatic oldest-record eviction via \texttt{removeBottom()}, and real-time command coalescing. In parallel, the task scheduler transitions from simple first-in first-out (FIFO) queueing to a multi-level priority queue with strict finalization barrier rules. This report provides:
\begin{enumerate}
    \item Mathematical correctness proofs of coalesced brightness inversion under pixel saturation.
    \item Concrete specifications of memory-aware history management and bottom eviction.
    \item Multi-level priority scheduler invariants, tie-breaking mechanisms, and finalization barriers.
    \item Empirical benchmark comparisons over a 30-job standard workload.
    \item Complete automated test verification across all criteria outlined in Section 7.7.
\end{enumerate}

\section{Memory-Aware History Management (Section 7.1)}

\subsection{Design Rationale: Beyond Full-Frame Snapshots}
In Phase 1, each undoable action stored a complete deep copy of the image matrix ($W \times H \times 3$ bytes) on the history stack. On high-resolution canvases, 50 operations consume hundreds of megabytes, inducing heap fragmentation. Phase 2 introduces specialized \textbf{compact inverse records}:
\begin{itemize}
    \item \textbf{Global Linear Adjustments (Brightness, Grayscale):} Stores an integer delta $\Delta B \in [-255, 255]$ and a compact list of clipped pixel coordinates and original channel intensities.
    \item \textbf{Geometric Transformations (Rotation, Flip):} Stores only the inverse operation ID (e.g., Undo for $90^\circ$ clockwise rotation is $270^\circ$ clockwise rotation; Undo for horizontal flip is horizontal flip). Memory footprint: $\mathcal{O}(1)$ (exactly 24 bytes).
    \item \textbf{Localized Region Modifications (Bucket Fill):} Rather than storing the full canvas, the record captures the original color, replacement color, and an array of modified coordinate pairs.
    \item \textbf{Destructive Dimension Changes (Crop, Resize, Blur):} A tightly bounded previous matrix is preserved, with its exact byte footprint charged against the global memory budget.
\end{itemize}

\subsection{Memory Budget Enforcement and Oldest-Record Eviction}
The \texttt{HistoryManager} enforces a configurable memory budget. If $\text{CurrentUsage} + \text{RecordSize} > \text{MemoryBudget}$, the manager invokes \texttt{stackType::removeBottom()} to evict the oldest history entry at index 0 in $\mathcal{O}(S)$ time, decrementing the byte counter until sufficient budget is freed.

\section{Command Coalescing and Invertibility Correctness (Section 7.2)}

\subsection{Mathematical Proof: Correctness of Coalesced Brightness Under Saturation}
\textbf{The Saturation Problem:} Simply applying $-\Delta$ on saturated values corrupts original intensities.

\noindent \textbf{Lossless Inversion Proof:}\\
Let an image matrix pixel have original channel intensity $P_0 \in [0, 255]$. Suppose a sequence of $m$ brightness adjustments with deltas $\{\delta_1, \delta_2, \dots, \delta_m\}$ are applied consecutively, with cumulative delta $\Delta = \sum_{i=1}^m \delta_i$.
\begin{enumerate}
    \item \textbf{Partitioning the Pixel Domain:} The pixel domain $\Omega = \{0, \dots, W-1\} \times \{0, \dots, H-1\}$ is partitioned into non-clamped and clamped sets:
    $$\Omega_{\text{normal}} = \{(x, y) \mid 0 \le P_0(x, y) + \Delta \le 255\}, \quad \Omega_{\text{clipped}} = \Omega \setminus \Omega_{\text{normal}}$$
    \item \textbf{Case 1: $(x, y) \in \Omega_{\text{normal}}$.} Here, $P_m(x,y) = P_0(x,y) + \Delta$. Applying the coalesced inverse delta $-\Delta$ produces:
    $$P_{\text{restored}}(x,y) = P_m(x,y) - \Delta = (P_0(x,y) + \Delta) - \Delta = P_0(x,y)$$
    \item \textbf{Case 2: $(x, y) \in \Omega_{\text{clipped}}$.} In this case, information is destroyed by saturation:
    $$P_m(x,y) = \begin{cases} 255 & \text{if } P_0(x,y) + \Delta > 255 \\ 0 & \text{if } P_0(x,y) + \Delta < 0 \end{cases}$$
    To maintain strict invertibility, the coalescing engine records a \texttt{ClippedPixel} entry:
    $$\text{record.clippedList}[\dots] = \{(x, y, P_0(x,y))\}$$
    When undoing, the algorithm first computes $P(x,y) = \text{clamp}(P(x,y) - \Delta, 0, 255)$, and then explicitly writes back the exact original intensities from \texttt{clippedList} for all $(x, y) \in \Omega_{\text{clipped}}$.
\end{enumerate}
Therefore, $\forall (x, y) \in \Omega$, $P_{\text{restored}}(x, y) \equiv P_0(x, y)$. The transformation is provably lossless. \hfill $\blacksquare$

\section{Scheduler Design and Priority Invariants (Section 7.3 and 7.5)}

\subsection{Scheduler Priority Classes}
Tasks are scheduled through a 4-tier priority model implemented via a custom sorted array structure (\texttt{priorityQueueType<Job>}):
\begin{itemize}
    \item \textbf{Priority 1 (Interactive / Real-Time):} Undo, Redo, Zoom, Viewport updates (Target latency $< 16 \text{ ms}$).
    \item \textbf{Priority 2 (Light Transformations):} Box Blur, Bucket Fill, Brightness adjustments (Target latency $< 50 \text{ ms}$).
    \item \textbf{Priority 3 (Heavy Computations):} Bilinear Resizing, Multi-pass convolutions, Complex filters.
    \item \textbf{Priority 4 (Finalization Barriers):} Save Project, Export Image to disk.
\end{itemize}

\subsection{The Finalization Barrier Rule}
\textbf{Invariant Formulation (Barrier Rule):}
Let $B$ be a barrier job (Save/Export) enqueued at discrete sequence timestamp $t_B$. Let $J$ be any arbitrary job enqueued at timestamp $t_J$.
$$\forall J \text{ with } t_J > t_B, \quad \text{ExecutionTimestamp}(J) > \text{ExecutionTimestamp}(B)$$
No job enqueued after a barrier may execute before that barrier, regardless of its priority rank. In ImageLab, this is enforced by partitioning the priority queue into barrier epochs: tasks within an epoch are prioritized, but barrier tasks serialize execution across epochs.
